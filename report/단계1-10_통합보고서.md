## 1~2단계. 환경 준비와 설치

Jetson 한 대를 세 계정(aip-1, jiwon, seohyun)이 함께 쓰도록 나눴다.

| 스크립트 | 실행 계정 | 하는 일 |
|---|---|---|
| `system_setup.sh` | aip-1 (sudo, 장비당 1회) | apt 패키지, 최대 성능 모드, 스왑 8GB, 공용 모델 캐시 `/ssd/hf`, `aiplab`·`video` 그룹 |
| `user_setup.sh` | 각 계정 (sudo 없이 1회) | venv `~/eg2`, Jetson용 PyTorch, sentence-transformers, `~/eg2-lab`, `eg2` 단축 명령 |

- 모델 파일은 `/ssd/hf` 하나를 공유하고, 파이썬 환경은 계정마다 따로 둬서 서로 영향을 주지 않게 했다.
- PyPI용 torch로 덮어쓰이지 않도록 `torch-pin.txt`로 버전을 고정한 뒤 패키지를 설치했다.
- `check.py` 결과: `torch 2.14.1+cu132 cuda True`, 모델 로드 후 `(768,)` 출력 확인.
- 공통 로더 `eg2.load(vision=False, audio=False)`는 필요한 인코더만 올리고, float16 대신 bfloat16을 쓴다 (float16은 NaN 발생).

## 3단계. 텍스트 임베딩

### 차원별 검색 (`test_text.py`)


| 차원 | 지연 | "수업 중에 졸리고 머리가 맑지 않아요" | "여름에 냉방 몇 도로 맞춰야 하나요?" |
|---|---|---|---|
| 768 | 185 ms | CO2 문서 (0.717) ✅ | 에어컨 문서 (0.725) ✅ |
| 256 | 177 ms | CO2 문서 (0.734) ✅ | 에어컨 문서 (0.754) ✅ |
| 128 | 175 ms | CO2 문서 (0.785) ✅ | 에어컨 문서 (0.810) ✅ |

- 세 차원 모두 정답 문서가 1위였다.
- `truncate_dim`은 768차원을 계산한 뒤 앞부분만 자르므로 인코딩 시간은 거의 같았다. 이점은 저장 공간과 유사도 계산에서 생긴다.
- 차원이 줄수록 점수가 높아졌지만, 차원이 다르면 점수의 절대값은 비교할 수 없어 1위 유지 여부로 판단했다.

### prompt_name을 뺀 비교 (`test_text_noprompt.py`)


| 질의 | prompt 있음 (768) | prompt 없음 (768) |
|---|---|---|
| 졸리고 머리가 맑지 않아요 | CO2 문서 (0.717) ✅ | 조도 문서 (0.747) ❌ |
| 냉방 몇 도로 맞춰야 하나요? | 에어컨 문서 (0.725) ✅ | 에어컨 문서 (0.823) ✅ |

접두어를 빼자 원인을 묻는 질의에서 1위가 증상이 비슷한 오답 문서로 바뀌었다. 접두어가 없으면 점수는 전반적으로 높아지지만 구분력은 떨어진다. 비용 차이가 없으므로 검색에는 항상 `prompt_name`을 붙인다.

### 동영상 검색 (`test_video.py`, 3,718 ms)


`{"video": "clip.mp4"}`는 torchcodec이 없어 실패했다. Jetson용 torch와 맞는 torchcodec이 없어서 PyAV로 초당 1프레임(10장)을 직접 뽑아 넘겼다.

| 질의 | 점수 |
|---|---|
| 모니터와 페트병이 놓인 빈 책상 | **0.713** |
| 강의실에 앉아 있는 학생 | 0.695 |

### 8-2 확인할 점

- 바로잡힌 라벨: 건전지(cell phone/bed → 건전지), 세탁기(microwave → 통돌이 세탁기, 종류는 틀림)
- COCO 물체(컵, 노트북, 휴대폰)는 재라벨 후에도 그대로 맞았다.
- 한계: YOLO가 박스를 잡지 못한 전지 포장은 고칠 기회가 없었다. 목록에 없는 물체(Jetson 보드)는 가장 비슷한 라벨이 억지로 붙었다. 1·2위 점수 차가 대부분 0.05 미만이었다.

### 추가 관찰

- YOLO는 납작하고 검은 직사각형(전지 포장, 건전지, Jetson 보드, 텀블러 뚜껑)을 cell phone이나 mouse로 몰아가는 경향이 세 모드 모두에 남았다.
- 빨간 니트를 입은 사람의 팔이 person이 아닌 teddy bear, airplane, dog, cat, bed로 잡혀 크롭이 저장되었다. 오인식이 개인정보 보호 장치(`SKIP_CLASSES`)까지 우회할 수 있다는 뜻이다. 해당 크롭은 이 저장소에 올리지 않았다.
- 확인 포인트: 평균 fps가 모두 10 이상이라 해상도를 낮추지 않았다. 크롭을 임베딩하는 순간 일시적으로 5fps 안팎까지 떨어졌다. 크롭은 촬영당 수십 장 수준이라 `REFRESH_S`도 기본값(30초)을 유지했다.

### 정리

정확도는 yoloe가 가장 높았다. COCO 밖 물체 중 드럼 세탁기와 건전지 낱개를 정확한 이름으로 검출했고, relabel에서 미검출이던 전지 포장에도 박스를 만들었다. relabel은 추가 학습 없이 건전지와 세탁기의 라벨을 바로잡았지만 YOLO가 박스를 잡지 못한 물체는 고칠 수 없었다. 속도는 yolo(12.1fps) > relabel(10.8fps) > yoloe(10.0fps) 순이었고 메모리 차이는 약 250MB로 작았다.

강의실 서비스에는 yoloe가 적절하다. 강의실에는 COCO 80종에 없는 장비가 많아 검출 단계부터 원하는 이름으로 찾는 방식이 유리하고, 10fps는 실시간 모니터링에 충분하다. 다만 휴대폰과 비슷한 납작한 물체는 세 모드 모두 헷갈렸으므로 LABELS에 더 구체적인 이름을 넣고 실제 강의실 사진으로 검증해야 한다.

## 9단계. 사람 동작 인식

`pose_app.py` (YOLO11n-pose, 관절 17개). 사람 이미지는 저장하지 않는다. 기록은 `log_pose.sh`(5초마다 모드, fps, 인원, 동작 횟수, RAM)와 `pose_summary.py`로 정리했다.

### 9-4 결과 (9-1 raw vs 9-2 개선)


| 동작 | 실제 횟수 | 9-1 raw | 9-2 개선 (smooth) | 비고 |
|---|---|---|---|---|
| 만세 | 1 | 1 | 1 | 두 방식 모두 정확 |
| 한팔들기 | 1 | **3** | 0 | raw는 깜빡임과 손 흔들기 오인으로 3번. smooth는 손 흔들기로 바로 넘어가 0번 |
| 손흔들기 | 1 | **0** | **1** | raw는 한 프레임만 보고 판정해 구분 못 함. smooth는 1.5초 손목 움직임으로 WAVE 인식 |
| 악수 | 1 | 1 | 0 | smooth 기록 중에는 화면에 1명만 있어 측정 불가 |

| 모드 | 검출 fps | RAM (MB) |
|---|---|---|
| raw | 약 11.7 | 약 2,830 |
| smooth | 약 11.7 | 약 2,865 |

raw는 프레임마다 판정해서 손 흔들기를 한팔들기로 오인했고, 판정이 깜빡이며 횟수가 실제보다 늘었다. 0.6초 다수결과 1.5초 손목 좌우 움직임 판정을 추가한 개선 버전은 손 흔들기를 따로 인식했고, 만세와 손 흔들기 횟수가 실제와 같았다. 대신 라벨이 바뀌기까지 약 0.5초 지연이 생겼다. EmbeddingGemma를 쓰지 않아 8단계보다 메모리를 약 2GB 덜 썼다.

### 9-5 행동 패턴


| 시나리오 | 기대 패턴 | 맞은 횟수 | 틀린 경우 나온 패턴 |
|---|---|---|---|
| 그냥 지나감 | 지나감 | 1 / 1 | - |
| 걸으며 2초 봄 | 힐끗 봄 | 1 / 1 | - |
| 멈춰서 5초 봄 | 관심 있음 | 2 / 2 | - |
| 옆을 보며 15초 서 있음 | 머무름 | 0 / 1 | 관심 있음 (체류 20초 중 정면 10초) |

웹 화면의 동작 기록이 최근 20줄만 보여 시나리오별로 확인된 시도 수가 1~2회다. 머무름은 옆을 봤는데도 정면 판정이 길게 나와 관심 있음으로 분류되었다. 판정이 시선이 아니라 머리 방향(코가 두 눈·귀 가운데 있는 정도)이기 때문이다. 한 사람이 머무는 동안 상태가 지나감 → 힐끗 봄 → 관심 있음으로 계속 바뀌었고, 최종 판정은 도달한 가장 높은 단계라 관심 있음 쪽으로 쏠렸다.

## 10단계. USB 카메라 2대로 특정 물체 접근 감지

지원 님(jiwon 계정)과 함께 같은 Jetson(aip-1)에서 진행했다 (2026-10-28 ~ 10-30). 사람 이미지는 저장하지 않고, 남는 것은 바닥 좌표와 알람 기록뿐이다.

### 10-1 렌즈 보정

| 카메라 | RMS (px) | fx | fy | cx | cy |
| --- | --- | --- | --- | --- | --- |
| cam0 USB | 0.215 | 426.6 | 428.5 | 372.6 | 216.2 |
| cam1 IP | 0.291 | 456.5 | 604.2 | 319.8 | 247.6 |

- 체커보드는 A4 인쇄물을 상자에 붙여 썼다 (완전히 평평하지는 않음).
- 처음 IP 카메라 RMS는 2.4~3.6px였고 cy가 −133으로 비정상이었다. 모서리 보정 창(cornerSubPix 11px)이 640×480 화면의 칸 간격보다 컸기 때문이다. 창 크기를 칸 간격에 맞게 자동으로 정하고 고차 왜곡 계수 k3을 고정하자 0.291px가 됐다.
- IP 카메라는 fx와 fy가 약 1.32배 다르다. 848×480 영상을 640×480으로 가로만 줄였기 때문이며, 보정이 이 찌그러짐까지 함께 잡는다.
- 흔들린 사진을 막으려고 체커보드가 멈춰 있을 때만 찍고, 오차가 큰 사진은 빼고 다시 계산했다.

### 10-2 위치 보정

**좌표계**: README의 축(x = 칠판 따라 오른쪽, y = 교실 뒤쪽, z = 위)은 왼손 좌표계(거울상)다. 그대로 계산하면 solvePnP가 "뒤를 보는 카메라"를 답으로 내서 위치 추정이 실패한다(시뮬레이션으로 확인). 그래서 오른손 좌표계(원점에서 x를 바라볼 때 y가 왼쪽, z 위)로 바꿨다.

**첫 장소 (사물함 벽 → 책상, 10-29)**: 기준점 8개가 책상 근처 40×50cm 안에 몰려 재투영 3.87 / 6.91px, 카메라 위치 오차 64 / 47cm로 실패했다. 시뮬레이션에서는 몰린 점이 카메라 위치 오차 16~30cm, 넓게 퍼뜨린 점 6개를 더하면 5~8cm였다. 이 결과로 장소를 바꿨다.

**새 장소 (열린 바닥 + 의자, 10-30)**: 기준점 14개(계산용 12개 + 검증용 C, d). 바닥 A~H 8개, 의자 등받이 a·b(0.85m), 의자 좌판 c·d(0.45m), 벽 e(1.45m)·f(1.25m).

| 항목 | cam0 USB | cam1 IP | 기준 |
| --- | --- | --- | --- |
| 재투영 평균 mean_px | 6.64 | 5.57 | 3 이하 |
| 가장 큰 점 | e 16.7px | a 11.0px | |
| 계산 위치 (m) | (0.93, 0.82, 1.01) | (0.30, 1.56, 1.20) | |
| 줄자 위치 (m) | (0, 0, 1.45) | (0, 1.40, 1.45) | |
| 차이 | 131cm | 42cm | 20cm 이내 |

두 카메라 삼각측량 오차(줄자 좌표와의 차이, cm): B 1.4, E 1.5, f 3.5, c 3.9, b 3.9, D 5.1, F 5.8, e 6.3, H 7.3, a 8.3, G 9.7, **C 11.2(검증)**, A 18.9, **d 21.2(검증)**.

- 기준에는 못 미쳤지만, 실제 위치 계산에 쓰는 삼각측량 오차가 14개 중 11개에서 10cm 이하라 실습을 그대로 진행했다.
- 두 장소 모두 계산된 카메라 높이가 실측보다 40cm 이상 낮았다. 줄자 측정 오차인지 클릭 오차인지는 확인하지 못했고, 이 높이 오차가 10-5의 실패로 이어졌다.
- 설치 조건의 한계: 두 카메라가 같은 벽에 1.4m 간격으로 있어 의자 위치에서 두 시선 각도가 약 18도로 작았다(권장 60~90도). 렌즈 높이 1.45m도 서 있는 사람 어깨(1.3~1.4m)와 거의 같았다.

### 10-3 ~ 10-5 실행 기록

타겟 = 의자 좌판 가운데 (2.4, 3.0) 직접 지정, `--near 1.0`, `--far 2.0`. README의 3m는 이 공간에서 카메라 범위를 벗어나 2m로 줄였다.

**10-3 ankle1 (카메라 1대 + 발목)**
- 근접 알람은 1.0m 안에서 정상으로 떴다(#2, #4, #5).
- '접근 시작'이 여러 번 찍혔다. #4는 4초 동안 1.8 → 0.5m로 6번 찍혔는데, 확인해 보니 실제로 여러 번 다가갔다.
- 이탈 알람(2.0m)은 한 번도 뜨지 않았다. 2m 밖으로 가기 전에 화면 밖으로 나가거나 발목이 안 보여서 '퇴장'으로 끝났다.
- 화면 가장자리에서 잠깐 잡혀 머문 시간 0초로 사라지는 짧은 트랙(#1, #3)이 있었다.

**10-4 stereo (두 카메라 + 어깨 삼각측량)**
- 의자 옆에 서 있을 때 거리 0.54m, 자세 '섬'으로 맞게 나왔다.
- 근접 알람 정상(#1 0.5m, #2 1.0m, 0.2m까지 접근 기록).
- 카메라 쪽으로 가까이 오면 위치가 사라졌다. 한쪽 화면에서 몸이 잘리면 두 카메라 짝이 맞지 않기 때문이다.

**10-5 fused (stereo + 한 카메라 추정)**
- 의자 근처에서는 stereo와 같았다(0.54m, 섬, near).
- 한 카메라에만 보일 때의 single 점은 처음 한 번만 나오고 이후 나오지 않았다. 두 화면에 모두 보이는데 카메라 가까이에서 위치가 없는 경우도 있었다.
- 원인: single은 시선이 높이 1.2m(가정한 어깨 높이) 평면과 만나는 곳을 위치로 잡는다. 10-2에서 카메라 높이가 1.01 / 1.20m로 계산돼 카메라가 그 높이보다 낮거나 같았고, 아래를 내려다보는 시선은 1.2m 평면에 닿지 않아 결과가 '없음'이 된다. 카메라 가까이에서 사라지는 것은 보정 오차로 재투영 오차가 짝짓기 기준(15px)을 넘은 것으로 보인다.
- 고치려면 10-2를 다시 해서 카메라 높이가 실측(1.45m)에 가깝게 나와야 하고, 카메라를 어깨보다 확실히 높은 곳(1.8m 이상)에 두는 것이 좋다.

- 의자 박스 중심은 사람 어깨보다 안정적이어서 사람 위치보다 삼각측량이 잘 맞았다(재투영 0.5px).

### 배운 점

1. 위치 보정의 질은 기준점 배치가 좌우한다. 한곳에 몰린 점은 카메라 위치를 50cm 이상 틀리게 한다. 넓게, 높이를 섞어 퍼뜨려야 한다.
2. 보정 숫자(mean_px, 카메라 위치)가 나빠도 타겟 근처의 삼각측량은 쓸 만했다. 하지만 카메라 가까이나 한 카메라 추정처럼 보정 오차가 커지는 곳에서는 바로 무너졌다.
3. 카메라 설치 조건(높이 1.8m 이상, 시선 각도 60~90도)은 계산 방식의 전제다. 카메라 높이가 가정한 어깨 높이보다 낮으면 한 카메라 추정(10-5)은 원리상 동작할 수 없다.
4. 물체(의자)는 사람보다 삼각측량이 잘 맞는다. 박스 중심이 안정적이기 때문이다.

## 진행하며 해결한 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 동영상 디코딩 `ImportError: torchcodec` | Jetson용 torch와 맞는 torchcodec 없음 | PyAV로 프레임을 직접 뽑아 넘김 |
| `sudo apt install espeak-ng` 실패 | 사용자 계정에 sudo 권한 없음 | 맥북 `say`로 음성 생성 후 전송 |
| `/dev/video0` 없음 | 웹캠 USB 데이터 연결 불량 | 포트를 바꿔 다시 연결 |
| 10-1 IP 카메라 RMS 2.4~3.6px, cy −133 | cornerSubPix 창이 칸 간격보다 큼 | 창 크기 자동 조정, k3 고정 → 0.291px |
| 10-2 solvePnP가 뒤를 보는 카메라를 답으로 냄 | README 좌표축이 왼손 좌표계 | 오른손 좌표계로 변경 |
| 10-2 카메라 위치 오차 50cm 이상 | 기준점이 한곳에 몰림 | 장소를 바꾸고 기준점을 넓게, 높이를 섞어 배치 |
| 웹 화면이 다른 페이지로 열림 | 맥북 8000번 포트를 다른 프로그램이 사용 | SSH 터널 포트를 8001로 변경 |
| `address already in use`, 웹캠 열기 실패 | 이전 앱이 꺼지지 않음 | `pkill -f pose_app.py` 후 재실행 |
| YOLOE 실행 중 torch 덮어쓰기 위험 | ultralytics의 자동 pip 설치 | CLIP을 `-c torch-pin.txt`로 미리 설치 |

### 참고

- 맥북과 Jetson 창을 헷갈리지 않도록 프롬프트로 구분했다: `...MacBookAir %`는 맥북(scp, ssh만), `(eg2) seohyun@aip-1:~/eg2-lab$`는 Jetson.
- 웹 화면은 `ssh -o ServerAliveInterval=30 -L 8001:localhost:8000 seohyun@<Jetson IP>`로 터널을 연 뒤 `http://localhost:8001`로 봤다.
- 긴 설치는 SSH가 끊겨도 계속되도록 tmux 또는 nohup으로 실행했다.
